# Бритва — запись в барбершоп через Telegram

Бот записи к мастеру и сайт салона в одном процессе: клиент выбирает услугу,
мастера, день и время кнопками в чате, бот напоминает о визите, администратор
видит расписание и управляет графиком прямо в Telegram.

**Живой бот:** [@britvaa_demo_bot](https://t.me/britvaa_demo_bot) ·
**сайт салона:** https://salaneze.github.io/barber-booking-demo/

Сайт отдаёт GitHub Pages (`.github/workflows/pages.yml`), бот живёт на Render.
Бот на бесплатном тарифе засыпает без сообщений — первый ответ может прийти
через минуту.

Барбершоп, мастера и адрес вымышленные — это демо, которое я настраиваю под
салон заказчика: услуги, мастера и часы работы задаются в одном файле.

## Что умеет

**Клиенту.** Запись в четыре шага: услуга → мастер → день → время. Показывается
только реально свободное время с учётом длительности услуги, графика мастера и
чужих записей. Свои записи можно посмотреть, перенести или отменить — не позже
чем за `CANCEL_HOURS` до визита, дальше через администратора. Напоминания за
сутки и за два часа.

**Администратору.** Новая запись приходит сообщением. `/admin` — расписание на
сегодня, завтра и послезавтра, отмена записи с уведомлением клиенту, выходные
дни мастеров.

**Сайт.** Прайс, мастера, график и FAQ собираются из тех же данных, что у бота,
поэтому цены на сайте и в чате не расходятся. Кнопка «Записаться» у услуги
открывает бота сразу на нужном шаге (`t.me/<бот>?start=s<id>`).

## Стек и решения

- Python 3.12, aiogram 3, SQLAlchemy 2 (async); SQLite локально, Postgres на хостинге.
- **Двойная запись исключена на уровне базы.** Вся запись идёт через одну функцию
  `repo.create_booking`: она заново считает свободное время под блокировкой
  мастера, поэтому два клиента, нажавшие одно время одновременно, не попадут
  в один слот. Тест на гонку проверен мутацией — без блокировки он падает.
- Свободное время — чистая функция без базы (`bot/slots.py`): расписание в местном
  времени салона, в базе UTC. Сразу после чужой записи время предлагается вне
  сетки, чтобы 45-минутная стрижка не оставляла дыр.
- Потолок активных записей на человека: один аккаунт не забьёт неделю всем мастерам.
- На хостинге — webhook и сайт одним aiohttp-процессом; путь и секрет вебхука
  выводятся из токена.

## Запуск

```
python -m venv .venv && .venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env   # заполнить BOT_TOKEN и ADMIN_IDS
python -m bot
```

При первом запуске база заполняется демо-услугами и мастерами (`bot/seed.py`).

Деплой на Render — `render.yaml` (Blueprint). Нужен внешний Postgres в `DB_URL`:
SQLite в контейнере стирается при каждом деплое.

## Тесты

```
python booking_test.py   # слоты, запись, перенос, отмена, гонка
python web_test.py       # webhook, раздача сайта, закрытые пути
```

## Структура

- `bot/slots.py` — расчёт свободного времени
- `bot/db/` — модели и репозиторий
- `bot/handlers/` — `client.py` (запись), `admin.py` (`/admin`)
- `bot/reminders.py` — напоминания
- `bot/web.py` — webhook и сайт
- `site/` — шаблоны сайта и сборка `build.py`
